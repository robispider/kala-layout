# বর্তমান ও আগের সিজন পুনরুৎপাদন

## বর্তমান কালা লেআউট প্রকাশনা

বর্তমান ফল একটি বিন্যাস, যার গতি/ঝড় টাইপিং স্টাইল। সংরক্ষিত গণনার তথ্য থেকে এর পোর্টেবল স্কোরার, রিপোর্ট, স্কোর, এক্সপোর্ট ও উদাহরণ আবার তৈরি করুন; টেক্সট নামানো বা নতুন সার্চ লাগে না:

```powershell
$env:PYTHONPATH = "src"
python -m bangla_dh challenge-kit
python -m bangla_dh publish-shared
python -m bangla_dh challenge-verify challenge/shared-v1/reference.json
python -m bangla_dh check-results
```

অভিন্ন স্কোরার মূল যাচাইকারীর সঙ্গে নির্ভুল পরিশ্রম, চলাচল ও আলাদা R স্বাধীনভাবে মেলায়। প্রায় 3 MB প্যাকেজে পাঁচটি উৎস ও দুই আঙুল-বিন্যাস আছে। বর্তমান চ্যালেঞ্জ নতুন অভিন্ন সিজন; মূল প্যাকেজ অক্ষত। দেখুন [সিদ্ধান্তের কারণ](SHARED_LAYOUT.md) ও [রিপোর্ট/ম্যানিফেস্ট](../results/shared-publication-v1/REPORT.md)।

পূর্ণ অভিন্ন সার্চের জন্য [চার-বিলিয়ন রানের রিপোর্টে](../results/shared-layout-relaxed-v1/run-4b-v1/REPORT.md) স্থির কমান্ড/সেটিং/সিড ও তার সোর্স সংস্করণ ব্যবহার করুন। পুরোনো রানের ইনপুট হ্যাশে সোর্স কোড আছে: পুরোনো রান পুনরুৎপাদনে নথিভুক্ত মূল Git সংস্করণ ব্যবহার করুন, বদলানো বর্তমান সোর্স নয়। পরিচিত আলাদা রাখা ডেটা আবার দেখা তথ্য। দ্রুত প্রকাশনা তৈরি করা চার বিলিয়ন প্রস্তাব আবার চালানো নয়।

[অভিন্ন বিন্যাসের প্রমাণে](SHARED_CERTIFICATION.md) দুই/তিনটি প্রতীক সরিয়ে পাওয়া সব ৪৫,৫২৬টি বিকল্প যাচাই করা হয়েছে। খালি ফোল্ডারে এটি আবার চালান, তারপর প্রকাশিত তথ্য স্বাধীনভাবে যাচাই করুন:

```powershell
$env:PYTHONPATH = "src"
python -m bangla_dh certify-shared --radius 3 --out work/shared-certificate-repeat
python -m bangla_dh verify-shared-certificate results/shared-certification-v1
```

## আগের আলাদা লেআউটের সিজন

নিচের কমান্ড ও সময় মূল গবেষণার। মূল generate-layout কমান্ড ও তার --reproduce বিকল্প এখনো আগের আলাদা ম্যাপ পুনরুৎপাদন করে, B01 নয়। স্পষ্ট legacy season বিকল্প পুরোনো বিল্ডার আলাদা রাখে। পুরোনো প্রত্যাশিত আউটপুট লকে থাকে, পাশাপাশি নতুন অভিন্ন গ্রুপ যাচাই হয়।


গবেষণাটি তিনটি গভীরতায় আবার চালানো যায়। প্রতিটি গভীরতা নিজেকে যাচাই করে `PASS` বলে, অথবা কোথায় ভিন্নতা তা দেখায়। সবকিছু Python 3.10 বা নতুন সংস্করণ ও স্ট্যান্ডার্ড লাইব্রেরিতে চলে; OR-Tools লাগে শুধু ঐচ্ছিক প্রমাণের জন্য।

PowerShell-এ নিচের কমান্ডের আগে `$env:PYTHONPATH = "src"` দিন, অথবা একবার `pip install -e .` চালিয়ে `python -m bangla_dh`-এর জায়গায় `bangla-dh` লিখুন। কমান্ডগুলো রিপোজিটরির ফোল্ডার থেকে চালান। একাধিক প্রসেসের কমান্ড কমান্ড লাইন থেকে শুরু করতে হয়, ইন্টারঅ্যাক্টিভ Python সেশনে টাইপ করে নয়।

## গভীরতা ১: সার্চ চালান

সার্চের দরকারি কি-স্ট্রোক সারণি `results/`-এ কমিট করা আছে, তাই কোনো ডাউনলোড লাগে না।

```bash
PYTHONPATH=src python -m bangla_dh generate-layout --style D --seeds 32
PYTHONPATH=src python -m bangla_dh generate-layout --style A --seeds 32
```

32 সিডের একটি সার্চ 8 কোরে কয়েক মিনিট নেয়। এটি এলোমেলো লেআউট থেকে শুরু করে, নিজের সেরা লেআউট ও প্রকাশিত লেআউট পাশাপাশি দেখায় (ট্রেনিং J1 ও তিনটি আলাদা রাখা J1), এবং বলে একই লেআউট পাওয়া গেল, ভিন্ন ও খারাপ কিছু, নাকি ভালো কিছু। ফাইলগুলো লেখা হয় `work/generate-<style>/`-এ, প্রকাশিত ফলের ওপর কখনো নয়। `D-layout.json` বা `A-layout.json` ফাইল [চ্যালেঞ্জ স্কোরার](CHALLENGE.md) দিয়ে স্কোর করা যায়।

অপশন:

* `--seeds N`: স্বতন্ত্র রানের সংখ্যা। প্রকাশিত লেআউটে পৌঁছানো গেছে 512টি শুরুর মধ্যে ঝড়ের 24টি ও গতির 36টি থেকে, তাই 32 সিডে এগুলো কখনো কখনোই পাওয়া যায়।
* `--first-seed N`: অন্য শুরু খুঁজতে সিডগুলো সরান।
* `--workers N`: কতগুলো প্রসেস ব্যবহার হবে।
* `--weights bnwiki/train=0.5 newspaper/train=0.5`: ট্রেনিং মিশ্রণ বদলান, যেমন শুধু উইকিপিডিয়ার জন্য `bnwiki/train=1`।

**প্রকাশিত** রান হুবহু আবার চালাতে (512 সিড, প্রকাশিত সিড-পরিসর, এবং আগের উইকিপিডিয়া ও সংবাদের লেআউট থেকে পালিশ):

```bash
PYTHONPATH=src python -m bangla_dh generate-layout --style D --reproduce --workers 28
```

32 কোরে এতে প্রায় 25 মিনিট লাগে; মিলে গেলে `the same layout as Kala Jhor` ছাপে, আর এক্সিট কোড 0 হয় শুধু তখনই।

## হুবহু মেলা এবং না মিললে কী করবেন

সার্চ নির্ধারিত: একই Python-এ একই সিড একই লেআউট দেয়। ফল আপনার প্ল্যাটফর্মের C লাইব্রেরির exp ফাংশনের ওপরও নির্ভর করে, তাই খুব ভিন্ন প্ল্যাটফর্মে অ্যানিলিং রান শেষ অঙ্কে সরে গিয়ে অন্য জায়গায় পৌঁছাতে পারে। চূড়ান্ত লেআউটগুলোতে অনেক স্বতন্ত্র সিড পৌঁছেছে, তাই ভিন্ন প্ল্যাটফর্মেও সেগুলো পাওয়া যায়। `check-results` যদি `DIFFERS` দেখায়:

1. ডাউনলোড নষ্ট হওয়ার সম্ভাবনা বাদ দিতে `verify-data` আবার চালান।
2. ইউনিট টেস্ট চালান: `PYTHONPATH=src python -m unittest discover -s tests` `OK` দিয়ে শেষ হওয়া উচিত।
3. আপনার অপারেটিং সিস্টেম, `python --version` এবং ভিন্ন ফাইলগুলোর নামসহ একটি ইস্যু খুলুন।

## ছোট কম্পিউটারে চালানো

যা সময় নেয় সবই সমান্তরাল। প্রসেস সীমিত করতে `--workers` ব্যবহার করুন, আর সার্চ ছোট করতে `mix-optimize --seeds 64` বা `generate-layout --seeds 16`। মনে রাখবেন, কম সিডে সেরা লেআউট কম বার পাওয়া যায়। জোড়া দেওয়া টেক্সটের জন্য 1 GB ডাউনলোডের ওপর প্রায় 4 GB ডিস্ক জায়গা লাগে।

## ধারাবাহিক টেক্সটের মূল্যায়ন (e3)

[ধারাবাহিক টেক্সটের প্রতিবেদন](../results/evaluator-e3/run-v1/REPORT.md) স্পেস ছোঁয়া তিন কী-এর উইন্ডো গোনে এবং মাঝখানে স্পেস থাকলে দুই প্রান্তের কীতে চলন দেখায়। এটি অতিরিক্ত বিশ্লেষণের মৌসুম; কোনো লেআউট নির্বাচন করে না এবং আনুষ্ঠানিক J1 স্কোর বদলায় না। টেক্সট না নামিয়েই সংরক্ষিত গণনা থেকে আবার হিসাব করুন:

```powershell
$env:PYTHONPATH = "src"
python -m bangla_dh.experimental.continuous_run --out work/evaluator-experiments/continuous-repeat --workers 4
```

নির্দিষ্ট হ্যাশে বাঁধা স্থানীয় করপাস ও টোকেন ফাইল থেকে আবার গুনতে `--rebuild-counts` যোগ করুন। ছোট আলাদা রাখা অংশটি আগে চালাতে `--heldout-only` ব্যবহার করুন। প্রতিবার আউটপুটের ফোল্ডার নতুন হতে হবে। পূর্ণ রানে মূল 50/50 মিশ্রণে A/D-এর প্রশিক্ষণভিত্তিক বিশ্লেষণ এবং দুটি আঙুল-বিন্যাসে সব ফিক্সড লেআউটের আলাদা রাখা টেক্সটের তুলনা থাকে। হুবহু গণনা যাচাই, এনকোডিং/পাঠের সময়, ক্যাশের আকার ও মেমরির মাপ প্রতিবেদনে আছে; সংরক্ষিত গণনা থেকে হিসাব করলে আগের সময়ের মাপই রাখা হয়।

## পরীক্ষামূলক যৌথ সার্চ (e4)

[যৌথ সার্চের পদ্ধতি](../results/evaluator-e4/README.md) কম J1 এবং স্পেসের দুই প্রান্তে একই আঙুলের ভিন্ন কীর মধ্যে কম চলন খোঁজে। মূল 50/50 প্রশিক্ষণ-মিশ্রণে একই স্টাইলের প্রকাশিত লেআউটের তুলনায় দুটিই কঠোরভাবে কম হতে হবে। আগের লেআউট ও ফল সংরক্ষিত থাকে; নতুন প্রার্থী ও তুলনা আলাদা ফোল্ডারে যায়। রিপোজিটরির মূল ফোল্ডার থেকে বিস্তৃত সার্চ চালান:

```powershell
$env:PYTHONPATH = "src"
python -m bangla_dh.experimental.joint_search --styles A D --seeds 512 --steps 1000000 --ils-iterations 1000 --archive-limit 64 --frontier-limit 32 --workers 28 --out results/evaluator-e4/rigorous-v1
```

এতে প্রতি স্টাইলে 512 সিড, মোট 1,024 রান হয়; টেক্সট না নামিয়েই সংরক্ষিত গণনা ব্যবহার করা হয়। পূর্ণ রানের সময় এখনো মাপা হয়নি। ছোট কম্পিউটারে `--workers` কমান। প্রতিটি নতুন রানের জন্য নতুন `--out` ফোল্ডার চাই। বাধা পড়লে একই কমান্ডে `--resume` যোগ করুন; আগের সম্পন্ন সিড ব্যবহার করার আগে কোড, ইনপুট ও সেটিংস যাচাই করা হয়। কর্মী প্রসেসের সংখ্যা বদলানো যায়। সম্পন্ন রান নতুন করে লেখা যায় না।

প্রতিটি প্রার্থীর প্রশিক্ষণভিত্তিক J1 আনুষ্ঠানিক স্কোরারের সঙ্গে হুবহু যাচাই করা হয়, সঙ্গে আলাদা চলনের স্কোর এবং মূল লেআউট থেকে পরিবর্তন থাকে। প্রতিবেদনে পাঁচটি উৎস ও দুটি আঙুল-বিন্যাস থাকে; আলাদা রাখা টেক্সট সার্চ বা নির্বাচনকে চালায় না। বেশি J1-এর বিনিময়ে চলন কমা দেখানো হয়, তবে সাফল্য ধরা হয় না। আর্কাইভের আকার সীমিত এবং তার সীমান্ত সব সম্ভাব্য প্রার্থী ধারণ করে না। ফল হলো পাওয়া সেরা, প্রমাণিত সর্বোত্তম নয়; যৌথ উন্নতি না পাওয়া মানে এমন উন্নতি নেই তা প্রমাণ হয় না। প্রকাশিত পুনরুৎপাদন লক, চ্যালেঞ্জ সংস্করণ ও ওয়েবসাইটের স্কোর অপরিবর্তিত থাকে।
